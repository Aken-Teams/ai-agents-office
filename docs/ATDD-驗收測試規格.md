# AI Agents Office — ATDD 驗收測試規格

> 版本 1.0 · 2026-06-12 · 對象:產品、QA、客戶驗收窗口
> 系列文件:**本篇 ATDD** ·〈BDD-行為測試規格〉·〈TDD-單元測試規格〉

## 0. 關於 ATDD(Acceptance Test-Driven Development)

ATDD 回答的是「**我們做對的東西了嗎?**」。在開發前,先由產品、開發、測試三方共同以**業務語言**約定「怎樣才算完成」(驗收準則),作為交付的唯一真相來源。

- **語言**:業務/客戶看得懂,不含實作細節。
- **層級**:功能驗收(端到端)。
- **與其他方法的關係**:ATDD 定義「要交付什麼」→ BDD 把每條驗收準則拆成可驗證的行為場景 → TDD 驅動每個單元的實作。

**驗收準則格式**:每條為可觀察、可驗證的陳述;每條都應對應一個可重跑的自動化驗收測試(見〈BDD〉)。

## 1. 功能範圍

| 編號 | 功能 |
|---|---|
| F1 | 使用者認證與登入防護 |
| F2 | AI 文件生成(PPT / Word / Excel / PDF) |

| F5 | 內容安全護欄 |

---

## 2. F1 — 使用者認證與登入防護

| # | 驗收準則 |
|---|---|
| AC-1 | 使用者以**正確**的電子郵件與密碼登入,可取得有效期內的登入權杖並進入服務。 |
| AC-2 | 輸入**錯誤**密碼時系統明確拒絕,且回應**不透露**帳號是否存在(防帳號列舉)。 |
| AC-3 | 同一帳號**連續失敗達門檻**後被**暫時鎖定**;鎖定於時間窗過後**自動解除**。 |
| AC-4 | 同一來源(IP)於短時間內**過量**嘗試會被限流,**即使更換帳號**仍受限。 |
| AC-5 | **停用 / 待審核 / 待驗證**之帳號無法登入,且訊息不洩漏內部細節。 |
| AC-6 | 登入**成功**後,該帳號先前的失敗計數歸零(不因舊失敗被誤鎖)。 |
| AC-7 | 密碼以**不可逆加密雜湊**儲存;密碼重設權杖為一次性、短時效且無帳號列舉。 |

**驗收佐證**:對應〈BDD〉Feature「使用者登入與暴力破解防護」;已於資安報告 §2 以動態驗證實測(連續失敗 → 423、逾量 → 429)。

---

## 3. F2 — AI 文件生成

| # | 驗收準則 |
|---|---|
| AC-1 | 使用者以自然語言描述需求,系統能產生對應格式檔(PPT / Word / Excel / PDF)並提供下載。 |
| AC-2 | 產生過程以**串流**即時呈現處理進度(代理活動、文字),使用者不需空等。 |
| AC-3 | 產生的檔案只存在於**該使用者、該對話**的專屬空間,其他帳號無法存取。 |
| AC-4 | 用量(token)依使用者**計量**;達額度上限時明確告知並停止處理。 |
| AC-5 | AI 回應中**不得**出現伺服器內部路徑或系統內部資訊。 |

---

## 4. F3 — 平台安全控制

| # | 驗收準則 |
|---|---|
| AC-1 | 所有回應均帶**安全標頭**(nosniff、HSTS、Referrer-Policy)且**隱藏技術棧**(無 X-Powered-By)。 |
| AC-2 | **未授權**或**偽造/竄改**權杖之請求一律被拒(401)。 |
| AC-3 | 正式環境的**錯誤回應**只給通用訊息,不洩漏堆疊、路徑或內部資訊。 |
| AC-4 | **過大**請求本體被拒;**跨來源**請求不反射未授權來源。 |
| AC-5 | 正式環境關鍵設定不正確(如預設密鑰)時**拒絕啟動**(fail-fast)。 |

**驗收佐證**:對應資安報告 §2「動態驗證結果」之 12 項控制。

---

## 5. F4 — 沙盒與跨帳號資料隔離

| # | 驗收準則 |
|---|---|
| AC-1 | 任一使用者的對話、檔案、記憶,其他帳號**完全無法**讀取。 |
| AC-2 | AI 工作目錄被限制在 `workspace/<userId>/<conversationId>/` 之內,**無法向上穿越**。 |
| AC-3 | 檔案下載端點**帳號範圍化**,且不洩漏他人檔案是否存在。 |

---

## 6. F5 — 內容安全護欄

| # | 驗收準則 |
|---|---|
| AC-1 | 涉及犯罪、入侵破壞、竊取機密、騷擾、危害他人、探詢本系統內部技術之請求,於**進入 AI 前**被攔截並記錄。 |
| AC-2 | 對外**拒絕訊息**不洩漏過濾規則之細節(避免被反向推測)。 |
| AC-3 | **合法**的防禦性資安、教育、研究、企劃等請求正常允許(不誤殺)。 |

---

## 7. 驗收簽核(Definition of Done)

一項功能視為「完成」需同時滿足:

1. 其**所有驗收準則**皆有對應且通過的自動化驗收測試(見〈BDD〉)。
2. 可在 staging 對相關人員**實機展示**。
3. 不造成既有功能回歸(回歸測試全綠)。
4. 安全相關項目另符合資安報告之控制要求。
