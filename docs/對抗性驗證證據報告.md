# AI Agents Office — 對抗性驗證證據報告

> Adversarial Validation Evidence Report · 版本 1.0 · 2026-06-12
> 本文件回應對〈資安評估報告 v1.4〉的核心批評:「驗證只有型別檢查 + 白箱自評,撐不起『已驗證』的強結論」。
> 在此**對執行中的系統實際發動攻擊**,以可重現的 HTTP / 函式級結果取代「型別檢查通過」。

## 0. 誠實的定位(先講清楚,避免重蹈覆轍)

- 本輪為**內部對抗性 / 動態測試** —— 對**執行中的系統**實際發動攻擊並記錄結果,**比型別檢查強非常多**,但:
- **仍非獨立第三方滲透測試 / 紅隊演練。** 要最高的對外公信力,該部分仍建議另行委外,本報告不假裝能取代。
- 結論只敢下到「**這些控制在本輪攻擊下守住了**」,不外推成「絕對無懈可擊」。

## 2. 跨帳號隔離 —— 實機 PoC(甲方最核心疑慮)· **13 / 13 通過**

> 開兩個真實的一般帳號,由 A **實際嘗試**存取 B 的資源。這是原報告只有「人工 code review」、被批評證據最薄的地方。

| # | 攻擊(A 對 B) | 預期 | 實測結果 |
|---|---|---|---|
| 控制組 | B 讀自己的對話 | 200 | **HTTP 200** ✓ |
| 1 | A 讀取 B 的對話(讀隔離) | 拒絕 | **HTTP 404** ✓ |
| 2 | A 改名 B 的對話(寫隔離) | 拒絕 | **HTTP 404**;B 標題未被竄改 ✓ |
| 3 | A 刪除 B 的對話 | 拒絕 | **HTTP 404** ✓ |
| 4 | A 把 AI 生成任務注入 B 的對話 | 拒絕 | **HTTP 404** ✓ |
| 5 | A 下載 B 的檔案(**同一 file ID**) | 拒絕 | **B=200 / A=404** ✓ |
| 6 | A 預覽 B 的檔案 | 拒絕 | **HTTP 404** ✓ |
| 7 | A 的檔案清單是否外洩 B 的檔案 | 不外洩 | **清單乾淨,不含 B 的檔案** ✓ |
| 8 | 一般使用者打 `/api/admin/*`(RBAC) | 拒絕 | **HTTP 403** ✓ |
| 9 | 未帶權杖存取 | 拒絕 | **HTTP 401** ✓ |
| 10 | 偽造權杖存取 | 拒絕 | **HTTP 401** ✓ |

**關鍵證據**:對**同一個檔案 ID**,擁有者 B 拿到 `200`、攻擊者 A 拿到 `404` —— 證明隔離不是「查無此物」的巧合,而是**以帳號歸屬實際阻擋**。技術根因:所有資源查詢均為 `WHERE id=? AND user_id=?`,且檔案下載另經 `validateFilePath` 二次校驗路徑歸屬。

## 3. 函式級對抗測試 —— **28 / 28 通過**

### 3.1 路徑穿越 / 沙盒(L-04)—— before / after PoC
| 攻擊 | 修補前(bare-prefix) | 修補後(現行) |
|---|---|---|
| 相似前綴 `workspace/alice-evil/secret` | **會放行(true)** | **擋下(false)** ✓ |
| 跨使用者 `workspace/bob/...` | — | 擋下 ✓ |
| `../` 正規化後跨界 | — | 擋下 ✓ |
| 合法自身路徑 | 放行 | 放行(無誤殺)✓ |

> 這正是甲方要求的「before/after 攻擊測試」:同一個 sibling-prefix 攻擊,舊邏輯**會放行**、修補後**擋下**。

### 3.2 ID 注入 / 輸入防護 / 檔名命令注入(L-01)
- `validateId`:`../etc`、`a/b`、`a;b` 皆**拒絕**;合法 ID 通過。
- `sanitizeUserInput`:`../` 穿越、`C:\Windows` 系統目錄**拋出拒絕**;`<system>` 注入標籤**被剝除**;正常文字不受影響。
- 檔名消毒(`fileRebuilder` 正式規則):`report; rm -rf ~`、`a$(whoami)`、`` x`id` ``、`y && curl evil`、`z|nc` 之危險字元 `; $ \` & |` **全部被消成 `_`**;正常中英檔名保留。

### 3.4 解壓炸彈(M-05)
| 攻擊 | 結果 |
|---|---|
| 114 bytes 之惡意 zip,中央目錄宣告解壓後 **954 MB**(膨脹比 ≈ **8,771,930 : 1**) | **拒收(zip_bomb_suspected)** ✓ |
| 合法 .docx(真實報告檔) | **通過(clean,無誤判)** ✓ |

> 偵測為**靜態解析中央目錄**(不解壓、無新增相依):總解壓量 > 600 MB 或膨脹比 > 200 即拒收。

## 6. 誠實的限制與未竟事項(這份不會假裝全包)

1. **非第三方 / 紅隊**:本輪為內部對抗測試。要最高公信力,仍建議委外滲透測試作為獨立佐證。
2. **提示注入(M-04)**:已測**輸入防護面**(路徑/標籤/系統目錄,§3.2);但對抗式 **AI prompt-injection robustness**(餵對抗樣本看 AI 會不會被操弄)未做 —— 該測試具機率性,需專門的對抗評估,**不宜宣稱 100% 擋住**。
3. **解壓炸彈(M-05)**:已補對抗 PoC —— 114 bytes 惡意 zip(中央目錄宣告解壓 954 MB、膨脹比 ≈8.7M:1)→ 拒收;合法 docx → 通過(無誤判)。
4. **H-01 / H-04(兩個 High 殘餘風險)**:補償控制之一部分已於 §2/§4 間接驗證(輸出不反射、RBAC、危險指令封鎖規則存在),但**帶日期的修補承諾**仍需業主提供 —— 不該用「改版時一併」這種無日期說法。
5. **資料在地化、稽核日誌保存/存取/防竄改**:屬政策面,需另以文件規範(Anthropic 處理區域、日誌保存期限與存取控制),本輪程式測試不涵蓋。
6. **M-11 的教訓**:此洞撐到 v1.4 才被動態測試抓到,本身即說明「只靠型別檢查的驗證深度不足」—— 這也是本報告存在的理由。
